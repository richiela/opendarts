# OpenDarts Changelog

Releases are listed oldest first. **Unreleased**, at the bottom, lists changes
made since the latest release.

## v0.81.1 (Sep 22, 2026)

- First public release. Camera-based automatic scoring for steel-tip darts: three commodity USB cameras watch the board, and when a dart lands the rig freezes a frame set and resolves a single `(sector, ring)` call. Four independent engines score every throw from different evidence — Apollo (3D from the dart tip), Talos (3D from the shaft, corrected to the sisal rather than the wire), Athena (2D, three separate per-camera calls combined by confidence), and Ares (2D, where the shaft lines cross) — with Zeus combining them by majority and Apollo holding the tie-break.
- **Replay packages.** Every scored throw can be saved with the exact inputs it was scored from — the empty-board frame, the scored frame and the calibration in force at capture — so the same throw re-scores through newer code and can produce a different, better answer. That is what makes an accuracy claim checkable rather than asserted.
- **One package shape.** A package is a few JSON files plus one MKV per camera holding the JPEG frames that were actually scored, with no re-encode. A throw not recorded as video keeps a two-frame clip — empty board, then scored frame — written the moment it is saved. With video on, a clip runs from the empty-board frame to one frame past the scored frame, both ends byte-identical to what the live scorer used and verified at write time; it replaces the two-frame clip only once every camera's clip has verified. `video_record_mode` chooses `all`, `mismatch` or `never`.
- **JPEG on every platform.** On Linux and Windows the cameras' own MJPEG bytes are stored as sent. macOS decodes MJPEG before any application can reach the bytes, so there OpenDarts encodes each frame to JPEG itself and scores the decode of those exact bytes — what is scored and what is stored match everywhere. Across 437 recorded darts from two camera models, a JPEG round trip anywhere from q100 down to q25 changed no score. `docs/CAMERAS.md` records what each camera actually sends.
- **No system ffmpeg.** Video is written through the PyAV wheel, which bundles the libraries; nothing shells out to an ffmpeg binary. A startup probe reports what external tools the rig actually has.
- **Autodarts as an optional oracle.** Each call can be compared against Autodarts to measure accuracy, with a whole-ring frame dump written when the two disagree. The Config tab shows the connection state live, in every open dashboard.
- **Throw viewer.** Any saved throw opens with when it was thrown, the package size and whether it holds a recorded clip, the visit's three darts beside the score — click one to step through the turn — plus the stills and a frame-by-frame clip scrubber.
- **Built for a screen nobody touches.** `?sound=on` in the dashboard URL turns spoken calls on for that screen. Open dashboards reload themselves when an update changes the page, and changes such as deleting recorded data reach every open screen.
- **Camera republishing.** OpenDarts hands its cameras on to other software on the same machine, so another scorer such as Autodarts can run beside it on the same board: Windows gets DirectShow virtual cameras and Linux v4l2loopback devices, and macOS needs neither because it shares cameras natively. `docs/STREAMING.md` has the details.
- **Network camera stream.** Every platform serves an HTTP MJPEG stream per camera, so other machines can watch the same board.
- Runs on Linux, macOS and Windows from a checkout, not a `pip install`. Dashboard and HTTP/WebSocket API on port 8420.
- AGPL-3.0-or-later. Issues welcome; pull requests cannot be merged yet — see CONTRIBUTING.md for why.

## v0.90.0 (Sep 26, 2026)

- **Summary.** A complete redesign of the interface, now built as a server and its clients: the rig serves one dashboard to any number of controllers and show-only displays, and keeps their settings itself. Under the hood the rig does less work — lighter detection, fewer package writes, and a board photo taken only when the board has changed.
- **A new dashboard.** `/` now serves a redesigned interface built on the same API, arranged by what the person in front of the rig is doing rather than by a sidebar of tabs:
  - **Play** is the scoreboard, made to be read from the oche: board and turn side by side on a TV, stacked on a phone, with the rig's state (stopped, starting, calibrating, offline) and Start on the board itself. Tap a dart to say what actually landed; "Missed a dart?" saves the frames from the turn it happened in.
  - **Throws** is history and accuracy. It opens on the Engines view — every engine's call side by side, struck through where it was wrong, Autodarts beside them — and follows the newest dart as it lands, with type sized to be read from about 8 ft and a per-screen Text size. A disagreement with Autodarts is shown as a dispute until someone says what landed; only a disagreement with a recorded answer counts as a miss. The detail pane plots every engine's point and Autodarts' on the real board.
  - **Rig** puts the cameras first — live previews, overlay, Calibrate, and where each camera sits (clock position, angle, distance) — then every setting as one row with its answer inline, virtual-camera health, screens, system and maintenance.
  - **Calibration shows its progress** full screen on every screen, the TV included: stage by stage, each camera working, done or given up, then how it ended (`CALIBRATION_PROGRESS`, `GET /api/calibration/progress`). Throws and Rig show a strip whenever the rig is offline, starting or not scoring.
  - **Displays.** `/?display=<id>` is the same page in a show-only role for a TV nobody touches: no bar, nothing to press, and it keeps itself awake. Its layout (Scoring + Engines, Scoring, or Engines), text size, board view, sound, voice and volume are set from any controller under Rig > Displays and pushed to it at once (`DISPLAY_UPDATED`); a display that reboots comes back the same.
  - **Calls arrive whole.** While spoken calls are on, the page keeps the audio output awake, so the first call after a break is no longer clipped by a TV or speaker waking from silence. Each screen reports audio stalls and output latency to the rig.
  - The fonts are embedded, so a rig with no internet keeps the design.
- **Upgrading from 0.81.** Every rig's `/` becomes the new dashboard on its first restart after updating. The classic dashboard is one switch away — Rig > System > Dashboard, or `/?ui=classic` for one screen — and `"dashboard_ui": "classic"` in `data/config.json` before restarting keeps a rig on it. Kiosk URLs written for the classic page, such as `/?sound=on#engines`, now open the new page (an unknown `#` section falls back to Play; `?kiosk=1` still hides the bar); a kiosk TV should move to `/?display=<id>&sound=on`. `data/config.json` gains `dashboard_ui` and `displays` sections as they are used; other keys are kept.
- **A real photo of your board on the scoreboard** — Play in the new dashboard, the Scoring tab in the classic one. The board is now a straight-on photo built from all three cameras, taken when you press Start and again after each takeout whenever the board looks different, with each dart drawn in where it landed as it looks from the oche: leaning the way it went in (exaggerated so the lean reads) and in its own flight colour, picked up from the cameras. A **Photo | Diagram** choice (This screen > Board in the new dashboard, a switch on the classic Scoring tab) brings back the drawn board; the choice is remembered per screen, and the diagram also shows until the first dart of a session has produced a photo. `THROW_DETECTED` now carries `dart_axis` and `flight_color` when they can be worked out, and the photo is served at `GET /api/board/photo`.
- **Less CPU watching an idle board.** Detection now reads each camera frame's JPEG decoded straight to a small grey picture, and decodes a frame in full colour only when it is scored or shown. On Linux and Windows cameras this roughly halves the capture and detection CPU; scores are computed from exactly the same pixels as before, though a dart may now be committed one frame earlier or later. `detect_from_small_decode: false` in `data/config.json` restores the old decoding.
- **One clip per package, written once.** A recorded throw's clip is now taken from the frame ring by frame number, checked byte-for-byte against the frames that were scored, and written a single time after the package's data, instead of a two-frame clip first and a rewrite later. In `mismatch` mode the clip waits for Autodarts' verdict before deciding. Clip writing and package loading decode only the frames they actually use, which on a Raspberry Pi 5 cut clip work per dart from about 0.4 s to a few milliseconds and package loads by two thirds.
- **Apollo no longer overrides its own answer on the strength of cameras that disagree about where the dart is.** When individual cameras out-vote Apollo's combined answer, the override now needs at least two cameras placing the dart within 10 mm of each other, and the position it reports must lie in the bed it calls. A double bull whose two outer-bull votes sat on opposite sides of the bull was called 25 from a position dead centre; that throw now scores 50. Across 1,120 recorded throws this changes one final call — that one — while every override the owner verified as correct still fires.
- **Smaller fixes.** The board photo always uses the calibration in force, and a recalibration retakes it. The rig gives a calibration's memory back to the operating system when it finishes; camera previews get their overlay back after returning to the tab and after Calibrate; the scoring board no longer nudges down on the first dart.

## v0.90.1 (Sep 26, 2026)

- **Pulling a dart out is no longer scored as a throw.** A takeout could be taken as finished while the hand was still pulling the last dart; that dart and hand then became the new empty board, and pulling it out read as a dart arriving where it had been. The rig now remembers the board as it was before a turn's first dart: a takeout finishes only once the board looks like that again where the darts were (or after about three seconds, so a dart left in cannot hold the board in the old turn), and a "dart" whose change puts the board back to that empty state is recognised as something removed and never scored. Replaying the 1,363 recorded throws changes no score and no takeout.
- The rig logs when it holds a takeout, when that hold ends (board empty, or timed out) and when a would-be dart turns out to be a removal, and keeps the frames of each refused removal (`removal-NNN`) so the decision can be checked afterwards.

## v0.91.0 (Sep 29, 2026)

- **Summary.** An accuracy release. Apollo and Talos now check each camera's reading against the other two views in 3D, Ares joins a dart that shows up in pieces, and Apollo, Talos and Athena follow a dart's needle past the point where it fades out of a camera's picture, so darts are placed where they really are. Replaying 1,934 recorded darts — 316 of them thrown after these changes were built — the final score agrees with the corrected answer on every one, against 1,927 with v0.90.1's engines. With Autodarts switched on as an oracle, the rig now waits for it and says so on every screen.
- **Darts are placed more accurately, especially near the treble and double wires.** Each camera used to decide on its own which shape in its picture was the new dart, so a flight, a neighbouring dart or a line along a wire could win, and the tip was often cut short where the thin needle fades against a dark bed. Now each camera's choice has to fit the other two views in 3D (the dart must lean the same way in all of them and its tip must land on the board), and the tip is found where the needle really ends rather than where it gets faint. Replaying 1,618 recorded darts, two that were scored wrong now come out right (a T12 and a T13 that had been read as singles), no dart that was right is now wrong, and the three cameras agree more closely on where each dart is.
- **Talos places darts more accurately.** Each camera's reading now has to fit the other two views in 3D, so Talos no longer takes a flight or the top of the dart for the tip. It also rejects camera pairs that "agree" on a point in front of the board, and no longer slides the point along an axis no dart could lean at. Replaying 1,931 recorded darts, Talos gets 10 more right and none worse.
- **Ares reads darts that show up in pieces.** A dark barrel over a black or green bed, or a thin shaft, can split a dart into several faint pieces, leaving that camera with nothing useful. Pieces that line up are now fitted as one dart. Replaying 1,931 recorded darts, Ares gets 11 more right and 1 worse.
- **Athena finds the needle past a gap.** On a dark bed the lower barrel and the needle can fade out of a camera's picture, so Athena used to stop the tip short, several millimetres off on the board. It now follows the dart down across the gap to where the needle ends; a single camera can no longer walk an off-board dart onto the board this way. Replaying 1,931 recorded darts, Athena gets 25 more right and 1 worse.
- **Apollo finds the needle past a gap.** When a dart shows up in pieces in a camera (the needle fading into the dark surround), Apollo used to stop the tip at the barrel, and two such cameras could put the dart in mid-air, off the board. It now carries the tip down the shaft to the needle, and keeps that only when it brings the dart onto the board. Replaying 1,934 recorded darts, Apollo gets 5 more right and none worse, and the final score is now right on all of them.
- **Talos finds the needle past a gap too.** The same fix as Apollo's: when a dart shows up in pieces, Talos carries the tip down the shaft to the needle and keeps it only when that brings the dart onto the board. Replaying 1,934 recorded darts, Talos gets 5 more right and none worse.
- **The oracle on every screen.** The oracle indicator shows what Autodarts' board is doing — grey offline, red stopped, yellow in takeout, blinking yellow when stuck, green ready — and runs it: its sheet has Start/Stop, Calibrate and Reset like the session sheet. The rig's own status light uses the same colours. While OD is holding for the oracle, Play and the kiosk show ON HOLD with the reason, and Reset reads "Reset OD + oracle". Throws filters are now All, Disputed, OD Wrong, AD Wrong, Split and No read; Rig > Virtual cameras says Idle when nothing is being published.
- **A change seen by one camera alone is no longer scored as a dart.** A hand behind the board, inside one camera's board area and invisible to the others, was scored as a run of OUTs. A dart lands on the board every camera watches, so a would-be dart now needs a second camera to see at least a trace of it; a change in one camera only is absorbed after a moment. Across 1,321 recorded darts the second camera never read below 20 changed pixels (the phantoms read 0), and replaying them changes no score.
- **OD no longer gets stuck in takeout after a clean pull.** Pulling darts could look like only some had been removed, and OD then waited for "the rest" until a reset. It now checks the board against the empty board it saw before the visit: if every camera matches, the takeout clears, and a visit stranded this way clears itself after a second.
- **With the oracle on, OD waits for it.** While Autodarts is stopped, offline or stuck in takeout, OD shows it is on hold and does not score, so a dart the oracle can't check never slips into a game. A dart thrown then is not scored: pull it and press Reset, which now resets Autodarts too.
- **Start, stop and reset Autodarts from OpenDarts.** `POST /api/oracle/{start|stop|reset}` makes the same local calls Autodarts' own dashboard makes on the board machine, so a board that stopped itself (it does after an hour stuck in a takeout) can be restarted without leaving OpenDarts. Refused while Autodarts is switched off.

## v0.91.1 (Oct 1, 2026)

- **Summary.** OpenDarts and its oracle now agree on what "ready" means. The rig tells you when Autodarts can't see or isn't running, starts it with one press, and the live feed reports starts, stops and takeouts accurately.
- **Start starts the oracle too.** With Autodarts on as the oracle and stood down (it stops itself after its idle time), Start in OpenDarts or FlightDeck now starts it as well. One press gets the board working, the way Reset already resets both.
- **The oracle shows red when Autodarts cannot see.** Autodarts reads its cameras through the rig, and after the rig has been down for about a minute it gives up on them for good, while still reporting itself ready. OD now watches its camera frame rate: no frames for 3 seconds turns the oracle red ("CAMERAS DOWN") and holds scoring until frames return.
- **"Waiting on oracle" is purple, not red.** When OD is running but held by the oracle, its light and status word now read purple, "Waiting on oracle: stopped" (or "cameras down" and so on). Red now means only OD itself is stopped.
- **Autodarts stands down with OpenDarts, not before or long after.** With the oracle on, Autodarts' camera standby time follows OD's idle timeout. It's set when OD connects and whenever the timeout changes, to the nearest of its choices (5, 10, 15, 30 or 60 minutes) that's at least as long.
- **A takeout waits for the darts to be out.** A takeout used to finish by itself about 3 seconds after the hand left, even with a dart still in. A relaxed pull could finish early and leave a dart in the board photo. It now waits until the board is empty; a dart left in keeps the rig in takeout, not scoring, until it's pulled or Reset.
- **The live feed reports takeouts, starts and stops correctly.** The retail feed that FlightDeck and the kiosk listen to now announces Start, a failed Start and Stop (including the idle timeout). It also reports the rig's own takeout from the end of the turn until the visit clears. Before, it missed takeouts entirely, flickered mid-pull, and could stay stuck in takeout after the board cleared.

## v0.92.0 (Oct 28, 2026)

- **The board photo no longer goes dark in the middle on rigs with low cameras.** The photo picks each spot from the camera that sees it most squarely, and on a rig whose cameras sit low the numbers behind that choice got so small they rounded away, leaving a dark shadow around the bull. The choice is now made relative to the best camera, so the centre comes out as bright as the cameras see it; rigs that never showed the shadow get the same photo as before.
- **Switching the cabinet lights on at Start no longer scores a phantom OUT.** The lights fade in and the cameras then adjust their exposure, so the change across the board shrank before it settled, and OD treated what was left as a dart against the dark board it saw at Start. It now waits for the board to settle and takes it as the new empty board. Across every session the reference rig has logged, the only decision this changes is that phantom.
- **A dart one camera sees whole and the others see only partly now scores.** OD scores a dart only when a second camera also sees it on the board, which stops hands and lights at the edge of one view scoring as ghosts. With cameras set low, a dart grouped with others could reach the other cameras only as a flight above the board and a hair-thin shaft, and was thrown away. OD now also counts a second camera that saw *the same dart*, worked out from the calibration: its change has to lie where that dart would appear from its angle. Of 1,242 single-camera trials on recorded darts, 1,241 pass; none of the 16 recorded ghosts do.
- **The console is readable again.** Some cameras pad every frame with a few junk bytes, and the JPEG library said so on the console for every frame decoded, up to 90 lines a second, burying the log. OpenDarts now drops exactly that harmless message and passes everything else through. `OPENDARTS_RAW_STDERR=1` shows it again for camera debugging. The log file was never affected.
- **A speck of change no longer confirms a one-camera dart.** The new same-dart check accepted a second camera with as little as 8 pixels of change, so switching the light strip off was confirmed as a dart (11 pixels) and scored OUT. A confirming camera now needs at least 50 pixels on the dart's band. Real darts never had fewer than 144 across 1,783 one-camera trials.
- **A dart that lands in front of a group now scores.** OD treated change that sat mostly on top of the darts already in the board as those darts being pulled out, so a third dart landing in front of two others was never scored (Autodarts scored it S20). That guard now waits until a pull-sized share of the darts has changed. Replayed over 68 logged sessions, it catches two real darts the old rule dropped and adds no phantoms. `docs/LIFECYCLE.md` now records every detection rule, what it separates and why.
- **A dart the oracle saw but OD missed is saved automatically.** With Autodarts on as the oracle, OD compares the two dart counts for the visit. If they disagree for 2.5 seconds, OD keeps the frame ring (no button needed, while the dart is still in it), logs what happened ("oracle saw dart 3 (S20) that OpenDarts did not") and tells every screen. The reverse, OD counting a dart the oracle did not, is caught the same way as a possible phantom. Autodarts never scores: the visit keeps the darts OD committed.
- **No yellow flash on the strip after the second dart.** A dart in flight passing in front of an earlier one looked, for one frame, like that dart being pulled, and OD briefly announced a takeout. OD now enters a takeout only on a still frame. When a visit clears is unchanged.
- **A restart or Reset with darts in the board no longer poisons later darts.** OD's picture of the empty board was taken once, at warm-up, so a warm-up with darts in it kept them in the "empty" board for good, and a later dart landing on one of those spots was refused as a removal. The picture is now retaken after every clean takeout.
- **Grouped third darts on low cameras now score.** A dart landing behind the first two can show less than 80 pixels in every camera, so OD never counted it, though Autodarts scored it from the same frames (T20, S20). The floor is now 60. Replayed over every logged session: both missed darts are caught, and everything else the lower floor admits is seen by one camera only, which OD already refuses.
- **A calibration loaded from disk shows its fit again.** After a restart the rig loads its saved calibration, and the dashboard showed only "Calibrated", hiding each camera's reprojection error until the next Calibrate. It now reads the error from the calibration's own saved record, so the badge and the Cameras table show it (and flag a loose fit) from the start.
- **Ares calls a dart off the board OUT.** Ares threw away any point where two cameras' shaft lines crossed more than 1.2 board radii from the bull. So for a dart that really missed the board, the only evidence left was whatever else changed on the board (a flight, a glint on a wire), and Ares scored the OUT as a hit. It now keeps those crossings, and the real dart, seen by two cameras, wins. Replayed over 3,473 darts with truth: Ares gets 8 more right and none wrong; the final score was already right on all of them, because the other engines outvoted Ares.
- **Autodarts no longer comes up stuck in takeout after Start.** Start started Autodarts the same instant, and the cabinet switched the board lights on a fraction of a second later, so Autodarts took its empty board in the dark, then saw the whole board change and went into a takeout that never ended. It happened on every cold Start. OpenDarts now starts Autodarts once its own warm-up has finished (every camera settled, about 3 seconds), when the lights are already on.
- **Stop stops Autodarts too, and Start straightens it out.** Stop left Autodarts running, so at the next Start the cabinet lights came on under it and it went into a takeout that never ended. Stop (and the idle stop) now stops it, the way Start starts it and Reset resets it. After a Start, OpenDarts waits until it has seen a still, empty board for 2 seconds (the lights on and the cameras settled; any change restarts the wait), then starts Autodarts, or resets one already running and stuck in a takeout with no darts thrown.
- **The three cameras can no longer drift out of step.** A camera's driver keeps a small queue of frames, and once it backed up it stayed backed up: on one evening one camera ran 4 frames (128 ms) behind for a whole session, and darts were committed before it had seen them. Each frame's capture time is now checked as it is read. A camera that falls behind has its queue drained to a fresh frame within milliseconds (logged), and a set of pictures not taken at the same moment is never used to detect or score a dart. `/api/cameras/status` shows each camera's frame age and drain count. See docs/CAMERAS.md.
- **Every saved dart can carry its score from the current code.** `python -m opendarts.capture.rescore_store` rescores the corpus and writes `rescore.json` next to each package: one entry per code version, in commit order, with the truth, the oracle's call and every engine's call. "Is this dart still wrong?" and "which change fixed it?" are now answered from the package, and each run logs accuracy per engine and the oracle's accuracy against the operator's corrections. `result.json`, the live score, is never touched. See docs/PACKAGES.md.
- **Ares calls a long miss OUT instead of giving no score.** Since Ares started keeping off-board shaft crossings, it could pick an off-board crossing, keep only the one camera that agreed with it, and then fail to place the dart: one shaft line with no tip point can't fix a position. It returned no score, though it had already worked out the dart was off the board. It now scores that off-board point, which is OUT. Two long-distance misses showed it, 236 and 311 mm out, and both now score OUT. Replayed over 4,087 darts with truth: every Ares call is unchanged; the case never occurred there.
- **Argus, a fifth engine, now votes in Zeus.** Argus reads what each camera sees at the needle tip (the board paint under it, the calibration map, how visible the needle's entry is, whether it sits on a dart thrown earlier in the visit) and lets the cameras' fused board position referee the vote. It votes last, so Apollo keeps the tie-break; when the other four split 2-2, Argus settles it by siding with one pair. Replayed over the 4,087 darts with truth: Zeus's misses go from 5 to 1 (4 fixed, none broken), and the other four engines' calls are unchanged. Argus always reports a board point, so its dot can be drawn beside the others. A rig whose `data/config.json` lists `also_run` explicitly needs `"Argus"` added there to store its column; Zeus votes with it either way.
- **Argus no longer calls a crowded third dart OUT.** With two darts already in the board, Argus's own tip finder took the flight end in one camera, an earlier dart's flight in another and a speck below the board in the third, so it called OUT while every other engine but one saw S16. When Argus's cameras do not agree on a point it now re-reads them from the blob in each camera that fits the other two views in 3D (the pick Apollo already makes), and scores the dart S16. Real misses still read OUT, since no blob fits on the board for them. Replayed over the 4,090 darts with truth: Argus gets 2 more right (this dart and one older one) and none wrong; Zeus and the other engines are unchanged.
- **A third dart grouped on the first two now scores even when every camera sees only a little of it.** Its flight landed on the earlier flights, so each camera saw less than the 60 pixels OD needs from one camera, and OD took it as background (Autodarts scored it S1). Two cameras that each see at least 40 pixels now count together, but only when what they see lines up as one dart in 3D and looks like a dart in both. Replayed from the missed dart's 20 seconds of video it scores; nothing else in those or four other recordings changes.
- **Cameras are read independently now, not in lockstep, and a set is never refused.** Each camera has its own reader, so one camera's driver queue can no longer back up on another's account — the cause of a camera running 4 frames behind for a whole session, and of the drain-and-refuse fix for that which then blinded a different rig for about 6 minutes when its own two thresholds disagreed about what "behind" meant. A set is now chosen by matching each camera's recent frames by capture time: a camera running behind is matched by the others reaching back into their own short history to the same instant, rather than the set being refused or the rig waiting on it. `drained_frames`/`drains` are gone from `/api/cameras/status`; `frame_age_ms` stays. See docs/CAMERAS.md.
